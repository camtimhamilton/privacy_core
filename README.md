# privacy_core

Ядро приватности для своей AI-ОС: шлюз между пользователем и внешними языковыми моделями, через который уходит только обезличенный текст, а ответ возвращается с восстановленными данными.

**Статус:** фаза 1 — архитектура и инварианты. Ядро собирается, контракты объявлены, тесты описывают требуемое поведение. Детекторов пока нет, и это осознанно: сначала фиксируются инварианты, которые фаза 2 не сможет нарушить незаметно.

## Быстрый старт

```bash
cargo test                                 # 142 теста проходят, 20 ожидают реализации
cargo run -p privacy-core-cli -- version   # версия ядра и протокола
cargo run -p privacy-os-truth -- --summary # что система знает о себе, без значений
cargo run -p privacy-os-truth -- --text "текст для проверки"
```

Команды `anonymize`, `restore` и `show` объявлены, но возвращают код 2: ядро ещё не обезличивает текст. Создавать видимость работающего продукта мы не хотим.

## Идея

Ядро приватности — изолированный модуль с версией, своими тестами и своими метриками, который ничего не знает об оркестрации LLM. Получает текст, отдаёт обезличенный текст и карту соответствий, умеет обратное превращение. Шлюз к моделям — первый потребитель ядра, а не его часть.

Причина такого деления: во всех существующих решениях приватность — это middleware, прикрученный к прокси. Из-за этого её нельзя ни измерить отдельно, ни переиспользовать, ни доказать её свойства.

## Что уже установлено (фаза 0)

Аудит нашёл вещи, которые меняют исходный план. Коротко:

| Находка | Следствие |
|---|---|
| Существует работающий проект [SurrogateShield](https://github.com/sherwinvishesh/SurrogateShield), который уже делает замену на похожие фейки, Relation Gate и риск-скоринг квазиидентификаторов | Два отличия из первоначального плана опровергнуты; отличие смещается на русский язык, вес и скорость |
| Задача контекстных утечек не решена нигде локально на CPU; для русского нет ни одной работы на стыке кореференции и приватности | Модуль контекста сужен до линковки ссылок на реестр сущностей; ворота go/no-go пройдены с условиями |
| Контрольные суммы не дают «нуля ложных срабатываний»: расчётный счёт проходит проверку у 10% случайных чисел | Формулировка заменена на измеримую метрику; для ряда типов контекст обязателен |
| Русские наборы данных с персональными данными существуют: 115 409 текстов, 24 типа, включая ИНН и паспорт РФ | Строить бенчмарк с нуля не нужно |
| Приказ Роскомнадзора № 140 задаёт закрытый перечень методов обезличивания, и ядро обязано поддерживать пять из них | Модель данных расширяется: метод у каждой подмены, оценка достаточности, экспортируемый протокол |
| Обратимая псевдонимизация не освобождает от согласия субъекта | Продукт нельзя позиционировать как «обезличили → согласие не нужно» |

Подробности и доказательства — в [аудите фазы 0](phase-0/01-audit.md).

## Что предполагается строить

**Ядро** (`privacy-core`) — на Rust, с биндингами для Python, Node и браузера через WebAssembly:

- форматные детекторы с контрольными суммами для российских реквизитов (ИНН, СНИЛС, ОГРН, ОГРНИП, паспорт, счёт, БИК);
- статистический распознаватель сущностей как сменный провайдер, не обязательная зависимость;
- генерация подмен: пять режимов по приказу № 140 плюс режим похожих фейков;
- карта соответствий с шифрованием, ключ отдельно от карты;
- восстановление ответа в несколько проходов;
- модуль контекстных ссылок (линковка на реестр сущностей диалога).

Три профиля задержки: быстрый (правила, ≤5 мс, ≤30 МБ), сбалансированный (≤25 мс, ≤250 МБ), максимальный (≤100 мс). Цель — то, чего нет ни у кого: полнота уровня лидеров при памяти в разы меньше и без обязательной нейросети.

## Что уже написано

Ядро — на Rust, с биндингами Python, Node и браузера через WebAssembly. Реализовано на фазе 1:

- **Типы и контракты**: границы спанов в байтах, ключ сущности с правилом нормализации, уровни уверенности, методы подмены по приказу № 140, поведение при сбое.
- **Решётка политик**: объединение политик только сужается, проверено полным перебором 216 политик.
- **Восстановление**: первый проход (точный, с проверкой границ слова в UTF-8) работает; проходы по частям и нечёткий объявлены.
- **Карта соответствий**: биекция «значение ↔ подмена» проверяется при вставке, коллизии отвергаются.
- **Инварианты I1–I10**: 20 тестов описывают требуемое поведение и пока помечены `#[ignore]`.
- **Форматный каскад**: ИНН (юрлицо и физлицо), СНИЛС, ОГРН, ОГРНИП — по структуре и контрольной сумме. Без нейросетей, без зависимостей. Вероятности ложных срабатываний сверены с отдельным замером.
- **Обезличивание работает целиком**: реквизиты заменяются, наружу не уходят, ответ модели восстанавливается.
- **Генератор подмен**: четыре вида — маркеры `[ИНН_1]`, маски `7707******`, похожие фейки и обобщения. Похожие фейки для ИНН, СНИЛС, ОГРН и ОГРНИП **проходят контрольные суммы**. Детерминированы от seed, коллизии исключены.
- **Идентификаторы устройства** (`crates/os-truth`): система точно знает домашний каталог, имя пользователя, имя машины, почту и имена проектов — это находится детерминированно, без модели. На реалистичных промптах: 4 из 4 с данными пойманы, контрольный без данных — чистый. Значения никогда не печатаются: только вид, длина и отпечаток.

## Лицензия

Apache-2.0. Без коммерческой части.

Выбор осознанный: лицензия не должна мешать коммерческому использованию, потому что тогда корпоративные потребители проходят мимо, а открытый проект без пользователей не имеет смысла. Патентная оговорка Apache-2.0 закрывает вопрос для корпоративного применения.

## Чего здесь пока нет

Поведения. Фаза 1 объявляет контракт: типы, трейты, инварианты и тесты, которые обязаны падать, пока поведение не реализовано. Детекторы, генерация похожих фейков, шифрование карты и модуль ссылок — это фаза 2.

Мы намеренно не публикуем обещания, которые не можем измерить. В документах аудита есть отдельные пометки «проверено», «по аннотации» и «не проверено», и последних немало.
