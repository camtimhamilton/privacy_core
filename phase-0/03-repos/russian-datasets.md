# Русские наборы данных для обезличивания: что реально есть

**Дата:** 2026-10-16
**Зачем:** был открытый вопрос фазы 3 — есть ли на чём строить бенчмарк для русского языка, или набор придётся создавать с нуля. Вопрос закрыт: есть, но с важными оговорками.

**Метод:** поиск по HuggingFace API, затем чтение схем и фактических строк через `datasets-server` и прямые ссылки на parquet. Всё, что ниже, проверено на данных, а не по описанию.

---

## 1. Главная находка

[`Powpowpow23/ru-pii-ner-data`](https://huggingface.co/datasets/Powpowpow23/ru-pii-ner-data) — русский набор с разметкой **российских реквизитов**, а не только имён.

| Свойство | Значение |
|---|---|
| Текстов | **115 409** (104 111 обучение, 11 298 проверка) |
| Размеченных сущностей | **495 948** |
| Типов сущностей | **24** |
| Лицензия | **Apache-2.0** |
| Происхождение | `synthetic`, `automatic_generation_and_span_tracking`, версия 0.1.0 |
| Датасет-версия | 0.1.0 |
| Группы происхождения | 24 444 (защита от утечки между обучением и проверкой) |
| Текстов без меток | 3 558 (готовый материал для замера ложных срабатываний) |

### Полный список типов

```
APARTMENT, BIRTH_PLACE, CARDHOLDER_NAME, CARD_NUMBER,
CITIZENSHIP, CITY, COUNTRY, CVV,
DATE_OF_BIRTH, DEPARTMENT_CODE, DISTRICT, DRIVER_LICENSE,
EMAIL, FULL_NAME, HOUSE, INN,
PASSPORT, PASSPORT_ISSUER, PASSPORT_ISSUE_DATE, PHONE,
PIN, POSTCODE, REGION, STREET
```

**Что здесь ценно именно для нас:**

| Тип | Почему важен |
|---|---|
| `INN` | Российский ИНН — наше отличие №1, и он размечен |
| `PASSPORT`, `PASSPORT_ISSUER`, `PASSPORT_ISSUE_DATE` | Паспорт РФ с полями выдачи — этого нет ни у кого из конкурентов |
| `DEPARTMENT_CODE` | Код подразделения — деталь, которую обычно пропускают |
| `DRIVER_LICENSE` | Вод. удостоверение |
| `CARD_NUMBER`, `CVV`, `PIN` | Платёжные данные |
| `REGION`, `DISTRICT`, `CITY`, `STREET`, `HOUSE`, `APARTMENT`, `POSTCODE` | Адрес разобран на части, а не одним куском |
| `CITIZENSHIP`, `BIRTH_PLACE` | Редкие типы, которые почти никто не размечает |

**Чего в нём нет:** СНИЛС, ОГРН, ОГРНИП, расчётного счёта, БИК. То есть части нашего реестра типов в наборе не хватает, и это надо дополнять своими примерами.

### Важные оговорки

1. **Набор полностью синтетический.** Авторы прямо пишут: `origin: synthetic`, сгенерировано автоматически с отслеживанием спанов. Это значит, что оценка на нём даст завышенные цифры относительно живого русского текста — ровно тот эффект, который SurrogateShield честно признаёт у себя: на вставленных значениях 0.8% утечек, на 96 реальных значениях в живом тексте — 30%.
2. **Данные перемешаны с обучающими.** Авторы предупреждают: это часть их данных дообучения модели A1, а не независимый тест. Использовать как есть для публикации результатов нельзя — нужна своя проверочная часть.
3. **Email и телефоны уже заменены** перед публикацией (`contact_policy: reserved_email_non_routable_phone`).
4. **Группировка примеров** (`group_id`) позволяет разделить по сюжетам, а не по строкам — это ровно то, что требует наш протокол (разделение по документам, а не по строкам).

### Разбор `wolframko/russian-pii-66k` (проверен на 100 строках)

Формат: `source_text`, `privacy_mask` (список спанов с `start`, `end`, `label`, `value`), `language`, `locale`. Всё, что я видел, — `locale: RU`.

Размеченные значения на 100 строках: 288. Что нашлось по российским шаблонам:

| Что искал | Нашлось | Пример |
|---|---|---|
| ИНН (10 или 12 цифр) | 12 (`TAXNUM`) | `659818733147` |
| СНИЛС (`XXX-XXX-XXX NN`) | 12 (`SOCIALNUM`) | `511-615-594 07` |
| IBAN | 26 (`ACCOUNTNUM`) | `RU45FOMI8350305641395` |
| ОГРН (13 цифр) | 0 | — |
| Паспорт РФ (4+6) | 0 | — |
| Расчётный счёт РФ (20 цифр) | 0 | — |

**Ключевая проблема этого набора:** счёт размечен как **IBAN** (`RU45FOMI…` — код банка из четырёх латинских букв), а не как российский расчётный счёт из 20 цифр. `IDCARDNUM` выглядит как водительское удостоверение (`11 95 956795`), а не паспорт. Телефоны вида `+7 (003) 791-76-93` не соответствуют российскому плану нумерации. Имена — редкие и явно сгенерированные.

**Вывод:** набор синтетический, использует международные шаблоны вместо российских реквизитов и не имеет указанной лицензии. Для сравнения он годится, для основной оценки — нет.

## 3. Что из этого следует для фазы 3

1. **Строить с нуля не нужно.** Основа есть: 115 409 текстов и 24 типа, включая ИНН и паспорт РФ.
2. **Своя проверочная часть обязательна.** Оба набора смешаны с обучением или синтетические. По нашему протоколу нужен замороженный `test`, не пересекающийся с `dev` — значит, его формируем сами поверх этих наборов, с разделением по `group_id`.
3. **СНИЛС, ОГРН, ОГРНИП, счёт, БИК придётся размечать самим.** В `ru-pii-ner-data` их нет, в `russian-pii-66k` счёт размечен как IBAN. Это работа, но она же и наше отличие: у конкурентов этих типов нет вообще.
4. **Нужен живой русский текст без персональных данных.** Для замера `FP(clean)` и для вставки значений в естественные носители. Источники: открытые корпуса русских текстов, документация, логи. Синтетика синтетикой, но без живых носителей цифры будут завышены.
5. **Лицензионная осторожность.** У двух наборов лицензия не указана. В основной бенчмарк берём только Apache-2.0 и MIT, остальные — как справочные, с оговоркой в отчёте.
6. **Проверить PII-Bench (ru)** — по сведениям потока по статьям, там 1 810 примеров и 13 типов с валидными контрольными суммами. Это может оказаться лучшей основой для соревновательного теста, чем оба набора выше. Задача фазы 0 — доделать проверку.
