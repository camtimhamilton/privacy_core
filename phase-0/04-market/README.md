# Рыночные продукты: что реально продаётся

**Дата:** 2025-10-16
**Назначение:** понять, кто уже занял корпоративную нишу, что заявляет и где остаётся место.
**Метод:** открытые страницы продуктов, отраслевые новости. Каждое утверждение помечено: **[ПРОВЕРЕНО]** — открыл страницу продукта; **[НОВОСТЬ]** — только из публикации; **[НЕ НАЙДЕНО]** — не нашёл.

---

## 1. Главный вывод

Рынок «шлюз, который прячет персональные данные перед отправкой в LLM» **уже сформирован**, и в России он плотнее, чем предполагал исходный план. План знал про одного игрока (StarGuard AI); в реальности их как минимум четыре, и один из них — крупный ИТ-дистрибьютор.

Второй вывод, важный для позиционирования: **все они делают маскирование на токены, а не замену на похожие фейки**, и у всех упор на корпоративные функции (роли, лимиты, аудит, несколько моделей). Именно поэтому план правильно ставил на open source и одиночек-разработчиков: в корпоративной продаже конкурировать бессмысленно.

---

## 2. StarGuard AI (Orion soft) — главный русский корпоративный продукт

**Источник:** [страница продукта](https://www.orionsoft.ru/starguardai), HTTPS 200, разобрана полностью. **[ПРОВЕРЕНО]**

| Свойство | Значение |
|---|---|
| Владелец | Orion soft — вендор серверной виртуализации, инфраструктуры и DevSecOps (zVirt, Nova, StarVault) |
| Реестр Минцифры | **№ 35067 от 07.09.2026** — то есть включён, как и предполагал план |
| Роль | Корпоративный reverse proxy между сотрудниками и LLM-провайдерами |
| Версия | 1.2 (новость от 28.09.2026) |
| Сценарий про персональные данные | Дословно: сотрудники отправляют документы с «ФИО, паспортными данными, **ИНН, СНИЛС** и адресами»; ML-детектор находит ПДн, система «маскирует их на спецтокены» до отправки, ответ «демаскируется обратно» |
| Провайдеры моделей | GigaChat, YandexGPT, ChatGPT, Claude, DeepSeek — облачные и локальные |
| Дополнительные функции | Фильтрация токсичного и запрещённого контента, защита от prompt-инъекций, OCR для PDF/XLSX/DOCX, учёт токенов и лимиты, ролевой доступ через корпоративный OpenID Connect (AD, KeyCloak, FreeIPA) |
| Целевой покупатель | Корпорация: CISO, подразделения HR, бухгалтерия, юристы, разработка |

**Что это значит для нас.**

1. **Русские типы ПДн в корпоративном продукте уже закрыты.** Тезис «у всех англоцентрично» неверен для российского рынка: StarGuard прямо называет ИНН и СНИЛС в сценарии.
2. **Замена — на спецтокены, не на фейки.** Значит, отличие «реалистичные подмены вместо заглушек» на этом рынке остаётся свободным, но это отличие качества ответа, а не функция, которой нет.
3. **Конкурировать по функциям нечем.** OCК-интеграция, роли, лимиты токенов, OCR, защита от инъекций — это корпоративный продукт с отделом продаж. Наш выбор — open source, одиночки, встраивание.

## 5. Что из этого следует для проекта

| Вывод | Следствие |
|---|---|
| Корпоративная ниша занята четырьмя игроками, один в реестре Минцифры | Подтверждает решение Р3: не идём в корпоративную продажу |
| Русские типы ПДн у корпоративных продуктов уже есть | Отличие «русский язык» в корпоративном сегменте не работает; работает в **open source и у одиночек**, где таких решений нет |
| Все делают токены, никто не делает фейки | Отличие «реалистичные подмены» сохраняется как отличие **качества ответа** |
| У всех упор на ролевую модель, лимиты, аудит | Для одиночки это шум; нам нужны CLI, демо и встраивание в редактор |
| Открытая библиотека «privacy gateway» на PyPI уже есть (`aigov-redact`) | Проверить при фазе 4: не пересекаемся ли мы с ними по аудитории |
